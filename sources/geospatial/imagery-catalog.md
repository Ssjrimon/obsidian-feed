# Sentinel imagery catalog

Feed-side scene lists for infrastructure and disaster work only. This is catalogue metadata from public STAC APIs. The collector does not download or process imagery, and it does not infer a cause from a satellite pass.

**Overhead is not imaging: a scene shows what was overhead and not why. Radar change is a lead and not confirmation.**

Generated by `collector/imagery_catalog.py`. The daily 7 AM CT refresh can rerun that script to regenerate the JSON under a rolling 30-day window (the previous same-orbit Sentinel-1 scene may sit up to about 18 days before a current pass, because the repeat cycle is about 12 days).

## What is in the tree

- `data/imagery/sentinel1/<region>.json` — recent Sentinel-1 GRD scenes over the watch points already used by the feed in that region, plus any confirmed-event places in the region. One scene is kept per pass (platform, relative orbit, orbit direction, and date). Each current pass is paired with the previous scene from the same orbit about 12 days earlier, when that pair exists in the catalogue.
- `data/imagery/before-after/<event-id>.json` — for each *confirmed* event only (unconfirmed and inferred items are ignored), the latest Sentinel-2 L2A scene before the event time and the latest scene after it, with cloud cover, date, a public STAC item link, and a public thumbnail URL when the catalogue exposes one.

Region file names are slugs of the feed `regionCode` values (`UKR-RUS` → `ukr-rus`, `RED SEA` → `red-sea`). `GLOBAL` has no coordinates and is omitted. The `MIDEAST` label is used as in the feed; no Jordan- or Amman-specific places are catalogued.

## Schema (Sentinel-1 region file)

`schema`: `obsidian-imagery-sentinel1-v1`

| Field | Meaning |
| --- | --- |
| `region` | Feed region code. |
| `generatedAt` | UTC time the file was built. |
| `windowDays` | Current-pass window (30). |
| `purpose` | Always infrastructure and disaster change-detection leads only. |
| `catalog` / `collection` | STAC catalogue and collection actually used. |
| `attribution` | `Copernicus Sentinel data [Year]`. |
| `caveats` | The overhead-is-not-imaging and radar-change-is-a-lead statements. |
| `aois` | Watch boxes that were searched (feed gazetteer points and/or confirmed places). |
| `passes[]` | One record per pass in the 30-day window. |

Each `passes[]` item:

| Field | Meaning |
| --- | --- |
| `sceneId` | STAC item id. |
| `acquisitionTimeUtc` | Acquisition time, UTC. |
| `orbitDirection` | `ascending` or `descending`. |
| `relativeOrbit` | Relative orbit number, when the catalogue provides it. |
| `footprintBbox` | `[west, south, east, north]` in lon/lat. |
| `stacItemUrl` | Public https STAC item. |
| `previewUrl` | Public https preview or thumbnail, when available. Requester-pays `s3://` asset hrefs are not stored. |
| `previousSameOrbit` | The matching earlier pass (~12 days), or omitted when none was found. Includes `daysEarlier`. |

## Schema (before/after file)

`schema`: `obsidian-imagery-before-after-v1`

| Field | Meaning |
| --- | --- |
| `eventId` | Matching id in `data/latest.json`, when the confirmed story is in the live feed. |
| `trendId` | Stable trend-watch id (T-019 in the first run). |
| `label` | Always `Confirmed` in this folder. |
| `eventTimeUtc` | Event time used to split before and after. |
| `place` | Public place name, region, coordinates, and search bbox. |
| `before` / `after` | Selected Sentinel-2 L2A scenes, or `null` if none met the window. |
| `before.cloudCoverPct` / `after.cloudCoverPct` | Catalogue `eo:cloud_cover`. |
| `before.date` / `after.date` | Acquisition date (UTC). |
| `before.stacItemUrl` / `after.stacItemUrl` | Public STAC item. |
| `before.thumbnailUrl` / `after.thumbnailUrl` | Public thumbnail, when available. |

Selection: among scenes in a 30-day window on each side of the event (the after window is clipped at "now"), keep the latest scene whose cloud cover is at or under 20%. If none qualify, keep the latest scene at or under 80% and record that fallback in `selection`.

## Catalogues, in order

1. Element 84 Earth Search STAC, `https://earth-search.aws.element84.com/v1` — default. Sentinel-1 collection `sentinel-1-grd`. Sentinel-2 prefers Collection 1 `sentinel-2-c1-l2a`, then `sentinel-2-l2a`.
2. Microsoft Planetary Computer STAC, `https://planetarycomputer.microsoft.com/api/stac/v1/` — fallback, search only, no SAS/blob download.
3. Copernicus Data Space STAC catalogue, `https://catalogue.dataspace.copernicus.eu/stac/search` — last fallback, unauthenticated catalogue search only. Authenticated download APIs are not used by this collector. Credentials, if present locally, are never read into these JSON files and must never be committed.

No login walls, no HTML scraping, and no systematic geocoding. Places come from the feed gazetteer and from published confirmed-event locations. Attribution for Sentinel products is `Copernicus Sentinel data [Year]` (or `Contains modified Copernicus Sentinel data [Year]` if a later step adapts the pixels, which this collector does not).

## How to read the files

A listed scene means a satellite was overhead and a GRD or L2A product was published for that footprint and time. It does not mean damage, flooding, a strike, or an outbreak is visible, and it does not confirm a news report. Same-orbit radar pairs are for an analyst or the app to inspect later; a difference between two scenes is a lead, not confirmation.
